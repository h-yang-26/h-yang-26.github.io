# Visual sources and accuracy notes

Every SVG in this folder is generated by [`scripts/build_visuals.py`](../../scripts/build_visuals.py)
(project figures), [`scripts/marketing_visuals.py`](../../scripts/marketing_visuals.py) (homepage tiles and
before/after banners) and the shared colours in [`scripts/visual_kit.py`](../../scripts/visual_kit.py).
Edit the data or layout there and rerun `build_visuals.py`; do not edit the SVG files by hand.
`python scripts/check_site.py` fails if the files or the recorded sizes in
`content/site.json` are out of date.

All figures use fictional data and summarize the independent public repositories,
**not proprietary workplace data, code, workflows or deployment architecture**.

## Variants

Each figure exists in up to three layouts, each in a light and a dark colour scheme:

| Layout | File | Used |
|---|---|---|
| wide (760 viewBox) | `name.svg`, `name-dark.svg` | project and Applied Thinking pages at 40rem and wider |
| narrow (420 viewBox) | `name-narrow.svg`, `name-narrow-dark.svg` | the same pages below 40rem (phones) |
| card (440 viewBox) | `name-card.svg`, `name-card-dark.svg` | homepage project cards, result figures only |
| tile (440 × 520 viewBox, one layout) | `tile-*.svg`, `tile-*-dark.svg` | "How I work" tiles; project links are HTML beside the tile |
| banner wide (1000) / narrow (420) | `ba-*.svg`, `ba-*-narrow.svg` (+ `-dark`) | before/after banners; the stacked narrow layout is used below 50rem (`narrowMax` in site.json) |

The site picks a variant with `<picture>` media queries for viewport width and
`prefers-color-scheme`, which works in Safari as well as Chromium and Firefox.
Headline titles are HTML (`title` in `content/site.json`), so the images hold data only.

Design rules applied by the generator:

- Minimum font sizes of 15 (wide), 16 (narrow) and 17 (card) viewBox units, about
  12 CSS px or more at the smallest width where each layout is shown.
- WCAG contrast checked on every run: 4.5:1 for text, 3:1 for bars, lines and borders.
- Colour has one meaning everywhere: blue = process or offer, teal = accepted,
  shipped or valid, amber = review, shortage or excluded, dashed = derived or
  uncommitted. Labels repeat the meaning in words, so colour is never the only cue.
- Bars are ranked by value unless the order is meaningful (funnel steps), labelled
  directly, and use horizontal text only.

regenerate. Never copy employer datasets or system diagrams into this directory.

## Applied Thinking diagrams

`thinking-foundations` and `thinking-cycle` are original explanatory diagrams. They
contain no measured data, employer architecture or numerical results. The cycle
illustrates reusable operations and revision, not a convergence guarantee. Alt text
and adjacent explanations are maintained in `content/site.json`.
